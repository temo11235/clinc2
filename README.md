# نظام إدارة عيادة الأسنان 🦷 (مصر)

نظام متكامل لإدارة عيادة أسنان خاصة في مصر: مواعيد، ملفات مرضى، سجلات علاجية، حسابات، تقارير، تذكيرات، ومساعد استقبال ذكي.

> **تنبيه مهم:** هذا الإصدار **بدون تسجيل دخول وبدون حسابات مستخدمين** بناءً على طلب العيادة.
> كل من يصل إلى رابط التطبيق يستطيع رؤية وتعديل كل البيانات. لذلك **يجب** نشره خلف حماية على مستوى الاستضافة
> (Vercel Password Protection / شبكة داخلية / VPN) — راجع `SECURITY.md`.

---

## 1) نظرة عامة

- واجهة عربية بالكامل مع دعم RTL.
- العملة: الجنيه المصري (تُخزَّن المبالغ كأعداد صحيحة بالقروش لتفادي أخطاء الكسور العشرية).
- التوقيت: `Africa/Cairo` في كل الحسابات والعرض.
- أرقام الهواتف المصرية تُطبَّع تلقائيًا إلى صيغة `+20…`.
- بيانات حقيقية في PostgreSQL عبر Drizzle ORM (لا توجد بيانات وهمية في الإنتاج).

## 2) المزايا المنفّذة

| الوحدة | التفاصيل |
|---|---|
| لوحة التحكم | مواعيد اليوم/المكتملة/الملغاة/عدم الحضور، مرضى جدد، التحصيل، المستحقات، صافي التشغيل، رسوم بيانية حقيقية |
| المرضى | CRUD كامل، بحث بالاسم/الهاتف/الكود، ترقيم صفحات، كشف التكرار بالهاتف، ملف المريض، مخطط الأسنان (FDI)، ملخص للطباعة |
| المواعيد | تقويم يومي/أسبوعي/شهري، حجز وتعديل وتأجيل وإلغاء، حالات الموعد، طابور اليوم، منع التعارض على مستوى التطبيق **وقاعدة البيانات** |
| السجلات العلاجية | زيارة سريرية (شكوى/فحص/تشخيص/خطة/متابعة/روشتة)، إجراءات بالسن والأسطح، قفل السجل لمنع التعديل الصامت |
| الحسابات | دليل علاجات وأسعار، فواتير (مسودة/نهائية)، بنود، دفعات جزئية، مرتجعات، مصروفات، ملخص خزينة يومي، تصدير CSV |
| التقارير | إيرادات/مصروفات، نسب الإكمال والإلغاء وعدم الحضور، أكثر الإجراءات، معدل عودة المرضى، أداء الأطباء، مصدر الحجز |
| المساعد الذكي | وكيل على الخادم يستدعي أدوات حقيقية (بحث عن مواعيد، حجز، تأجيل، إلغاء، تحويل لموظف) مع تحقق من الهوية وتأكيد صريح |
| التذكيرات | مهام مجدولة (Cron) للتأكيد وتذكير 24 ساعة وساعتين، منع التكرار، إعادة المحاولة، سجل إرسال |
| الإعدادات | بيانات العيادة، مواعيد العمل والراحات والإجازات، مدد المواعيد، قوالب الرسائل، الأسئلة الشائعة، إعدادات المساعد |
| الأطباء | دليل أطباء يُستخدم في توزيع المواعيد ومنع التعارض (بدون حسابات دخول) |
| سجل العمليات | تدقيق لكل عملية حساسة بدون أي بيانات طبية |

## 3) التقنيات

Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind CSS 4 · PostgreSQL · Drizzle ORM · Zod · Recharts · Vitest.

## 4) المتطلبات

- Node.js 20+ (تم الاختبار على 22)
- PostgreSQL 14+ (مع إضافة `btree_gist` المتاحة افتراضيًا)

## 5) التشغيل محليًا

```bash
npm install
cp .env.example .env          # عدّل DATABASE_URL
npm run db:push               # إنشاء الجداول
npm run db:constraints        # قيود منع التعارض والقيود المالية (مهم جدًا)
npm run seed                  # عيادة + أطباء + دليل علاجات
npm run seed:demo             # (اختياري) بيانات تجريبية خيالية
npm run dev
```

ثم افتح `http://localhost:3000` — ستنتقل مباشرة إلى لوحة التحكم (لا يوجد تسجيل دخول).
واجهة المرضى العامة: `http://localhost:3000/assistant`.

## 7) متغيرات البيئة

كلها موثقة في `.env.example`:

| المتغير | مطلوب | الوصف |
|---|---|---|
| `DATABASE_URL` | ✅ | رابط PostgreSQL |
| `CLINIC_ID` / `PUBLIC_CLINIC_ID` | ✅ | معرّف العيادة (افتراضي 1) |
| `ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` | ❌ | تفعيل المساعد الذكي الكامل |
| `AI_MODEL` | ❌ | اسم الموديل |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_VERIFY_TOKEN` | ❌ | تكامل واتساب |
| `RESEND_API_KEY`, `EMAIL_FROM` | ❌ | إرسال البريد |
| `SMS_API_KEY` | ❌ | مزود SMS (غير منفّذ بالكامل) |
| `CRON_SECRET` | ✅ للإنتاج | حماية مسار التذكيرات |
| `APP_URL` | ❌ | رابط التطبيق |

## 8) المساعد الذكي

- يعمل **على الخادم فقط**؛ المفاتيح لا تصل للمتصفح إطلاقًا.
- الأدوات المنفّذة: `get_clinic_information`, `search_available_slots`, `create_appointment`,
  `find_patient_appointments`, `reschedule_appointment`, `cancel_appointment`, `request_human_assistance`.
- كل أداة تتحقق من مدخلاتها بـ Zod، وتتحقق من هوية المريض برقم الهاتف (والاسم عند الاستعلام)، وتسجَّل في `ai_tool_audit_logs`.
- لا يؤكد المساعد أي حجز قبل نجاح الكتابة في قاعدة البيانات فعليًا.
- لا يشخّص ولا يصف أدوية، ويحوّل الحالات العاجلة لتعليمات الطوارئ المعتمدة + تحويل لموظف.
- **بدون مفتاح مزود**: يعمل وضع احتياطي قائم على القواعد يقرأ بيانات حقيقية (مواعيد متاحة/أسعار/عنوان) ويطلب تأكيد الاستقبال للحجز.

## 9) التذكيرات وواتساب

- عند الحجز تُنشأ مهام: تأكيد فوري + تذكير 24 ساعة + تذكير ساعتين (حسب الإعدادات) بمفتاح `dedupe_key` يمنع التكرار.
- المعالجة عبر `GET/POST /api/cron/reminders` مع `Authorization: Bearer $CRON_SECRET`، ومجدولة على Vercel كل 15 دقيقة (`vercel.json`).
- بدون بيانات اعتماد حقيقية تُستخدم محوّلات التطوير (تسجيل في لوج الخادم) ولا تُرسل رسائل فعلية، ويظهر ذلك بوضوح في صفحة التذكيرات.
- حالة "تم التسليم" تُسجَّل فقط عند استقبال Webhook من واتساب على `/api/webhooks/whatsapp`.

### إعداد واتساب
1. أنشئ تطبيقًا على Meta for Developers وفعّل WhatsApp Business Cloud API.
2. احصل على `WHATSAPP_PHONE_NUMBER_ID` ورمز وصول دائم `WHATSAPP_TOKEN`.
3. اضبط `WHATSAPP_VERIFY_TOKEN` بنفس القيمة في لوحة Meta وفي متغيرات البيئة.
4. اضبط عنوان Webhook: `https://YOUR-DOMAIN/api/webhooks/whatsapp` واشترك في حدث `messages`.
5. القوالب الجاهزة مطلوبة للرسائل خارج نافذة الـ24 ساعة (تحتاج اعتمادًا من Meta).

## 10) النشر على GitHub ثم Vercel

```bash
git init
git status
git add .
git commit -m "feat: dental clinic management system"
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

ثم على Vercel:
1. أنشئ قاعدة PostgreSQL (Neon / Supabase / أي مزود) واحصل على `DATABASE_URL`.
2. طبّق المخطط: `npm run db:push` ثم `psql "$DATABASE_URL" -f scripts/constraints.sql`.
3. شغّل `npm run seed` مرة واحدة لإنشاء العيادة ودليل العلاجات.
4. اربط مستودع GitHub بمشروع Vercel.
5. أضف متغيرات البيئة (خصوصًا `DATABASE_URL` و`CRON_SECRET`).
6. فعّل **Password Protection** من إعدادات المشروع (ضروري لعدم وجود تسجيل دخول داخل التطبيق).
7. انشر؛ مهمة Cron تُفعَّل تلقائيًا من `vercel.json`.
8. اضبط Webhook واتساب بعد النشر، ثم اختبر الحجز والتذكيرات والتقارير.

> لم يتم تنفيذ نشر فعلي على Vercel من داخل هذه البيئة — الخطوات أعلاه موثقة ويجب تنفيذها بحساب العيادة.

## 12) ما لم يُنفَّذ / يحتاج عملًا إضافيًا

- **الفاتورة الإلكترونية المصرية (ETA)**: الفواتير داخلية فقط ولا تُرسل لمنظومة مصلحة الضرائب — يلزم تكامل ومراجعة قانونية.
- **رفع المرفقات (أشعة)**: الجدول `clinical_attachments` موجود، لكن واجهة الرفع والتخزين الآمن غير مفعّلة في هذا الإصدار.
- **مزود SMS**: المحوّل موجود كهيكل فقط.
- **اختبارات E2E (Playwright)**: غير مُضافة؛ التغطية الحالية وحدات + تكامل قاعدة بيانات.
- **تسجيل الدخول والأدوار**: مُزال عمدًا بناءً على طلب العميل.

## 13) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `DATABASE_URL is required` | أنشئ `.env` من `.env.example` |
| لا تُمنع المواعيد المتعارضة على مستوى DB | شغّل `npm run db:constraints` |
| `/api/cron/reminders` يرجع 401 | اضبط `CRON_SECRET` وأرسله في ترويسة `Authorization` |
| المساعد لا يحجز تلقائيًا | أضف `ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` |
| التواريخ تبدو مزاحة ساعة | تأكد من أن كل الحسابات تمر عبر `src/lib/time.ts` |
